# 음성 전처리와 다운로드

회의, 강의, 면접 업로드 화면에서 잡음 감소, 앞뒤 잡담 제외, 전문용어 교정을 각각 켜거나 끌 수 있습니다. 기본값은 모두 켜짐입니다. 세 옵션을 모두 끄면 기존 전사 경로를 사용합니다.

## 처리 순서

1. 원본을 보관하고 작업용 16 kHz 모노 WAV를 만듭니다.
2. 주파수 영역에서 지속적인 백색 잡음을 줄입니다.
3. 선택한 STT와 화자 분리 모델로 전사합니다. 기본은 Qwen3-ASR와 단어 시간 정렬기, NVIDIA Nemotron 3입니다. 기존 CrisperWhisper와 pyannote도 선택할 수 있습니다. [음성 모델 선택](speech-models.md)을 참고하세요.
4. 녹음 종류와 제목, 강의명 또는 면접 직무 정보를 참고해 확실한 앞뒤 잡담만 제외합니다.
5. 전문용어 사전의 알려진 표기를 교정합니다.
6. 전처리 전사와 교정 전 전사를 각각 저장하고, 선택한 구간의 MP3 및 강의 MP4를 생성합니다.
7. 분석 단계는 전처리 전사를 읽되 발언 ID, 화자, 원본 시간을 유지합니다.

## 잡음 감소

별도 신경망 모델을 사용하지 않습니다. 녹음 전체에 걸쳐 최대 64개 구간을 샘플링하고 FFT로 평탄한 잡음 후보를 찾습니다. 이 구간의 하위 음량을 기준으로 FFmpeg `afftdn`의 잡음 바닥을 설정합니다. 70 Hz 고역 통과 필터와 최대 6 dB의 완만한 잡음 감소를 적용합니다. 음성으로 보이는 구간을 잡음으로 학습하지 않도록 후보가 부족하면 매우 낮은 잡음 바닥을 사용합니다.

필터는 무음이나 발화를 잘라내지 않습니다. 필터 전후 길이가 달라지거나 처리에 실패하면 잡음 감소 없이 전사를 진행합니다. 일정한 백색 잡음이 주 대상이며, 겹치는 다른 사람의 말이나 순간적인 충격음을 분리하는 기능은 아닙니다.

## 확실한 앞뒤 잡담만 제외

Claude가 녹음의 앞뒤 발언과 본문 일부를 읽고 경계를 제안합니다. 기본은 구성된 Opus 모델이며, 강의 설정이 Sonnet이면 해당 모델을 사용합니다. 다음 조건을 코드에서 추가 검증합니다.

- 본문 중간은 제외할 수 없습니다.
- 실제 원문에 있는 시작 또는 종료 안내 문구가 있어야 합니다.
- 자기소개, 후보자 경험과 답변, 후속 질문, 회의 결정, 강의 복습과 선수 지식 등의 단서가 있으면 해당 구간을 유지합니다.
- 한쪽에서 최대 10분 또는 전체의 20%까지만, 양쪽 합계로 최대 30%까지만 제외할 수 있습니다.
- 겹치는 발언을 중간에서 자르지 않습니다.
- 모델이 보지 못한 발언을 제외하지 않습니다.
- 근거가 부족하거나 모델 호출이 실패하면 전체를 유지합니다.

짧은 녹음은 판정을 생략합니다. 슬라이드 페이지 선택이나 특정 주제에 대한 요청만으로 다른 발언을 제외하지 않습니다. 모델의 높은 판단 점수는 정확도 보장이 아니며, 실제 제외 내역과 근거는 전사에 보관합니다.

## 전문용어 사전

초기 사전은 177개 항목으로 구성됩니다.

| 파일 | 내용 |
| --- | --- |
| [`aws.json`](../stt/src/stt/glossaries/aws.json) | AWS 서비스와 인프라 용어 78개 |
| [`ml.json`](../stt/src/stt/glossaries/ml.json) | 머신러닝, 딥러닝, 개발 용어 79개 |
| [`interview.json`](../stt/src/stt/glossaries/interview.json) | 면접, 역할, 리더십 원칙 용어 20개 |

`aliases`는 알려진 표기 변형, `contextAliases`는 주변 문맥이 필요할 때 사용하는 변형입니다. `reviewAliases`와 유사도 매칭은 확인 후보만 만들고 원문을 자동 변경하지 않습니다. 예를 들어 “람다”는 AWS Lambda와 수학 기호를 구분해야 하므로 확인 대상으로 둡니다. URL, 이메일, 코드 표기는 보호합니다.

사전은 오인식된 표기를 정규화하는 용도입니다. 후보자가 잘못 설명한 개념을 정답으로 고치지 않습니다. 교정된 발언에는 `originalText`와 교정 내역을 남기고, 원본의 단어별 시간 정보는 별도 원문 전사에 유지합니다. 사전 수정 시 JSON의 버전과 `terminology.py`의 `VERSION`을 함께 올립니다.

## 파일과 시간 기준

결과 화면의 **전처리 파일**에서 MP3, 강의 MP4, 원본을 다운로드할 수 있습니다. 파일 생성이 실패하면 원본을 계속 사용할 수 있고 오류 안내가 표시됩니다. 다운로드할 때 서명 URL을 갱신하며 대용량 파일을 브라우저 메모리에 통째로 올리지 않습니다.

- MP3는 전처리된 16 kHz 모노 음성으로 인코딩합니다. 원본 비트레이트를 참고해 최대 64 kbps로 저장하며, 원본이 16 또는 32 kbps라면 그 수준을 유지합니다. 원본 정보를 읽지 못하면 64 kbps를 사용합니다. 이전의 128 kbps 고정 출력과 달리 낮은 비트레이트의 녹음이 몇 배로 커지는 것을 방지합니다.
- MP4는 영상 스트림을 복사하고 음성만 전처리된 AAC로 바꿉니다. 영상 재인코딩을 피하기 위해 앞선 키프레임부터 시작할 수 있습니다. 따라서 MP3보다 앞부분이 더 포함될 수 있습니다.
- 원본 파일과 화면의 원본 재생 시간은 바꾸지 않습니다.
- 다운로드 파일의 0초에 해당하는 원본 시간을 화면, 파일명, 파일 메타데이터에 기록합니다.
- `transcript.json`은 분석용 전처리 전사, `transcript_original.json`은 구간 제외와 용어 교정 전 전사입니다. 이 “원문 전사”도 잡음 감소 옵션이 켜져 있으면 잡음 감소된 입력을 인식한 결과입니다.

기존에 완료된 기록은 캐시된 전사를 재사용하므로 새 전처리 파일이 자동 생성되지 않습니다. 새 기능을 적용하려면 원본을 새로 업로드해 전사부터 실행합니다.

## 운영

전처리 미디어는 각 기록의 `processed/{run-id}/` 아래에 저장합니다. 다운로드 API는 소유권과 기록별 키 경로를 확인합니다. 삭제 시에는 `stt/deleted/`에 표시를 먼저 남겨 실행 중인 전처리 작업이 파일을 다시 만들지 않도록 합니다. 이 표시는 기존 `stt/` 수명 주기 정책으로 만료됩니다.

배포할 때는 새 출력 형식을 읽는 API, 정규화 단계, 분석 런타임, 웹을 먼저 배포한 뒤 STT 엔드포인트를 교체합니다. 이전 형식으로 이미 대기 중인 요청은 기존 동작을 유지합니다.
